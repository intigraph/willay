Willay

Willay

Agents write the episode; Willay performs it. An agent-authored TOML script becomes multi-host ElevenLabs dialogue, local or generated effects, transitions, a ducked music bed, a measured MP3, chapters and show notes. An optional private RSS feed gives a listener one subscription.

Willay does not call a language model. Python 3.12+, uv and ffmpeg are its runtime; the pinned dependency supplies ffmpeg when the host has no system binary. Source, provider generation, host installation and phone playback are separately verified stages. Offline tones prove the audio pipeline, not generated speech.

Episode specification

The format is TOML. Host IDs reference voice IDs chosen from willay voices. Each segment contains exactly one say, sfx or transition. A chapter title on a segment introduces a topic boundary. The whole spec validates before any paid call, including all local assets.

title = "An evidence briefing"
description = "Source links and listening context go here."

[[hosts]]
id = "ana"
voice = "JBFqnCBsd6RMkjVDRZzb"

[[hosts]]
id = "rafa"
voice = "Aw4FAjKCGjjNkVhN1Xmq"

[[segments]]
chapter = "Welcome"
say = { host = "ana", text = "[curious] What changed?" }

[[segments]]
say = { host = "rafa", text = "Let's start with what was measured." }

[music] accepts intro/outro file paths and bed = { file = "assets/bed.mp3", gain_db = -24 }. A transition accepts { file = "assets/sting.mp3", crossfade_ms = 400 }. Effects accept a local file or a generated prompt plus bounded duration_seconds. Asset paths are relative to the spec. Use only assets you have listening rights for. Models are eleven_v3 or eleven_v4; expressiveness tags stay in turn text.

Rendering pipeline

Validate every host, turn and asset before generation. Consecutive turns form dialogue chunks with at most 2,000 characters and ten unique voices. More hosts can appear in later chunks; no turn is silently truncated.

The shared usage ledger reserves before each paid call. Content hashes bind model, text, voice and output format; checked successful takes are reusable. Ambiguous calls retain reservations and refuse automatic retry.

ffmpeg decodes originals, assembles ordered audio with transition crossfades, loops and ducks a quiet bed, then performs two-pass EBU R128 normalization. The encoded MP3 is measured again. manifest.json records actual duration, loudness and hashes; chapters.json and show-notes.md accompany it.

Publishing verifies those hashes, uses a stable GUID and updates RSS atomically. The authenticated reader supports byte ranges for podcast apps. Publication does not create host routing or authorize making a private feed public.

CLI

uv sync --locked
uv run --locked willay --version
uv run --locked willay budget examples/episode.toml
uv run --locked willay voices
uv run --locked willay render examples/episode.toml -o out/example
uv run --locked willay metrics

An already-approved private host can render and publish in one command:

willay render episode.toml -o out/episode \
  --feed-root /approved/feed --base-url https://podcasts.example.test

willay publish publishes an existing completed output. willay serve implements the separate authenticated reader for a reviewed service host; it is not a crew-session background launcher. The podcast skill is in skills/podcast.

Quality and documentation entry points are just check, just build and just docs. Release wheels and source archives carry published checksums.

Budgets and private feeds

Keys resolve at runtime from an already-held ELEVENLABS_API_KEY or an owner-only ELEVENLABS_API_KEY_FILE. The public default is ~/.config/willay/elevenlabs_api_key; deployments can point at an existing vault file. Keys never belong in TOML, source, subprocess arguments or output.

One shared rendering state directory enforces daily UTC ceilings of 20,000 dialogue characters, 30 generated-effect seconds and 20 paid calls. Every attempt reserves first; failures and ambiguous timeouts are not automatically refunded. This is a local reservation cap, not an account-global invoice meter. willay metrics reports usage and ceilings without script text or secrets.

The feed requires private HTTPS routing and authentication. Its reader requires Basic auth for RSS/media/HEAD, restricts served paths, refuses symlinks and supports byte ranges. The feed root must already be private before publication. Verify both unauthorized refusal and authenticated playback in the actual podcast app.

Personal listening is the intended use. Notes attribute generated voices to ElevenLabs; output rights still depend on account/service terms. Keep private sources and voices out of public repositories. Rollback disables the scoped feed/skill while retaining originals and the quota ledger.

Implementation and release design

Willay uses Python 3.12+ rather than a Rust skeleton. This keeps the existing cc-speaks credential client reusable and retains the tested HTTP, SQLite and ffmpeg pipeline in one implementation. TOML uses the standard library; ffmpeg performs the audio work as a bounded subprocess. The only runtime dependency supplies a packaged ffmpeg when the host has none. Python/uv are required; this is not a static native binary.

The repository follows the Yupana template for justfile quality/build/docs entry points, Apache-2.0 licensing, mdBook/Pages and same-workflow release artifacts with checksums. Python uses release-please as the language-appropriate release-PR equivalent; release-plz supports Rust packages. The release PR updates pyproject.toml, changelog and the marked root package version in uv.lock. The version exposed by the CLI comes from installed package metadata.

Artifacts are built from the actual version tag, checked against its independent version, and uploaded in the same workflow that creates the release, avoiding reliance on token-generated tag events. A manual existing-tag repair lane stays available. No automatic PyPI publication or registry-name claim is configured. Release PRs still need complete CI and an independent review before merging.

The agent authors scripts; Willay never calls a language model. Dialogue and effects reserve a conservative local budget before sending, retain ambiguous charges and skip content-identical successful takes. State is shared on one rendering host, not an account-global usage meter across unrelated products. A separate bounded authenticated feed reader serves only completed artifacts. Host installation, private TLS routing and phone playback remain separate from source controls.
